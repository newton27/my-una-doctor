MY UNA DOCTOR 0.6.5 — INSTALLATION & SAFETY GUIDE
===================================================

Product: My UNA Doctor
Vendor: My UNA World
Type: Studio-only UNA CMS module
Build: 0.6.5

IMPORTANT
---------
Create and verify a current backup before installing, updating or using any repair workflow.

My UNA Doctor contains read-only diagnostics plus guarded repair infrastructure. Diagnostic findings alone do not authorize changes.

1. BEFORE INSTALLING
--------------------
1. Back up the UNA database and site files.
2. Confirm the public site and UNA Studio currently load.
3. Record the site's UNA and PHP versions.
4. Do not manually edit UNA module-version database records.
5. Do not unpack the module into an extra nested directory.

The installed module directory must be:

    modules/newton/my_una_doctor/

2. INSTALL THROUGH UNA STUDIO
-----------------------------
1. Sign in as an UNA administrator.
2. Open UNA Studio.
3. Open the Modules / Apps area.
4. Upload/install the My UNA Doctor package using UNA's normal module workflow.
5. Confirm installation completes without SQL, language, class or compatibility errors.

3. CONFIRM THE STUDIO MODULE
----------------------------
Return to the Studio launcher and open My UNA Doctor.

The Studio icon is stored under the module template images path. Do not modify UNA core files if the launcher icon is missing; verify the module files and Studio registration first.

4. RUN THE FIRST HEALTH SCAN
----------------------------
Open My UNA Doctor and choose:

    Run Full Health Scan

Review:

- UNA Health percentage;
- Critical count;
- Warning count;
- compatibility results;
- maintenance and upgrade state;
- module integrity;
- update-readiness findings;
- database/filesystem/cron/log findings.

Warnings and informational findings should be reviewed before attempting a repair or upgrade.

5. COMPATIBILITY INTELLIGENCE
-----------------------------
Version 0.6.0 reads compatibility evidence from the installed UNA environment.

Doctor verifies the local UNA minimum PHP requirement, required PHP extensions, registered module compatibility declarations and declared dependencies.

When UNA advertises a newer target, Doctor may inspect official metadata. If the expected official upgrade ZIP is already staged, Doctor can verify its MD5, structure and target identity and perform limited static evidence inspection.

Doctor never executes the target package's check.php during an ordinary health scan.

Static evidence is not the same as a complete future-target preflight.

6. MODULE REFERENCE LIBRARY
---------------------------
Known-good or virgin module packages can be saved as repair references.

Reference packages are validated and fingerprinted before comparison. A reference does not authorize Doctor to overwrite the installed module automatically.

7. GUARDED REPAIR SAFETY
------------------------
Supported repair workflows are staged and evidence-driven.

Typical lifecycle:

    Scan
    Preview
    Preflight
    Arm Plan
    Explicit approval
    Durable rollback journal
    Protected mutation
    Validation
    Restore / merge
    Rollback when required

Do not bypass a failed preflight, unresolved journal or rollback warning.

8. RUNTIME-GENERATED MODULE CONTENT
-----------------------------------
Some third-party modules create large runtime trees inside their own module directories.

Doctor may identify this content separately from tracked source and report that it affects UNA Studio update readiness.

Do not re-baseline generated files simply to make the warning disappear.

Use a protected workflow that separates runtime content, verifies update readiness, performs the module update, restores/merges runtime content and verifies the result.

9. MAINTENANCE STATE
--------------------
Doctor reports UNA soft maintenance, hard maintenance locks, stale hard locks, possible interrupted upgrades and Doctor-protected repair state separately.

Doctor does not automatically delete .bx_maintenance merely because it exists.

10. EXISTING INSTALLATIONS
--------------------------
Do not uninstall a working My UNA Doctor installation merely to change versions.

Use the appropriate UNA update package/workflow supplied for the version being installed. Do not manually change sys_modules.version as a substitute for a real update procedure.

11. AFTER INSTALLATION OR UPDATE
--------------------------------
Run a fresh full health scan and confirm:

- My UNA Doctor reports the expected installed version;
- no unexplained Doctor tracked-file drift exists;
- UNA file/database versions agree;
- maintenance state is normal unless intentionally active;
- PHP and required-extension checks pass;
- module compatibility results are understood;
- any update-readiness blockers are reviewed before continuing.

Keep the verified backup until the site and Studio have both been confirmed stable.

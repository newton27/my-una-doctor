# My UNA Doctor 0.6.8 — scan maintenance

Full health scans now hold UNA native soft maintenance for the actual scanner and history-save duration. Public visitors see the configured Doctor page when enabled. Existing administrator maintenance and its page remain intact; page header, footer and text settings continue to apply. Template compression is temporarily disabled so Studio assets remain available.

The shared private lease blocks overlapping Doctor scans and My UNA World backup operations. Exact original native option values are journaled before changes, restored on success, exception and PHP shutdown, and preserved when a concurrent administrator changes them. Atomic conditional writes protect Studio saves. A new every-minute Doctor cron recovers an interrupted process only after obtaining its abandoned lock. A running process is never recovered based on elapsed time. Recovery requires functioning UNA cron and a writable site-parent directory for the private lock and journal.

The native maintenance value carries a unique truthy owner token so an administrator's ordinary `on` value cannot be mistaken for the scan's switch. The journal records pending and applied writes. If a process dies in the narrow compression-write checkpoint gap, recovery preserves direct assets and reports that field as preserved; it does not guess whether an administrator independently disabled compression. The owned public maintenance switch still recovers normally.

This release retains candidate 30d8885cb0503913358afe21ceacf3b647b725a3 compatibility declarations and System version provenance behavior. It adds new full-install and direct native updater archives from 0.6.1 through 0.6.7. Use the archive matching the exact installed version; live 0.6.4 uses the new 0.6.4-to-0.6.8 route. Version and modified-file gates remain enabled. The updater replaces files and executes only retry-safe registration of Doctor's recovery cron. It does not rerun full installation SQL or reset settings, scans, repair records or references.

Published tags, release assets and previous updater payloads are unchanged. Source checks cover native option lifecycle, failed startup/restoration, active ownership, concurrent Studio saves, process shutdown, SIGKILL recovery, standalone cron recovery, version provenance, package identities and isolated official updater contracts. Native Marketplace installation/update and public visitor acceptance must be recorded against the final source and package hashes. Source checks alone do not certify a live native update.
